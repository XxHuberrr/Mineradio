# Mineradio 本地曲库、歌单与歌词模式设计

## 目标

在不复制音乐文件、不破坏现有云平台播放链和 3D 视觉系统的前提下，为 Mineradio 增加永久本地曲库、本地混合歌单、登录感知搜索，以及三态舞台歌词和译文显示。

## 范围

- 本地曲库支持连续导入多个文件夹，跨重启保留并合并去重。
- 本地歌单支持本地、QQ、网易云歌曲混合保存和播放。
- 本地曲库支持单选、全选、反选、取消选择和批量加入歌单。
- 本地歌单支持创建、重命名、删除、查看、单首播放和播放全部。
- 搜索来源由当前登录状态决定，综合结果按本地、QQ、网易云排序并自动去重。
- 底部歌词按钮循环切换关闭、当前歌词、七节点滚动歌词。
- 译文由独立开关控制，并对不完全一致的时间戳进行容错对齐。

不在本次范围内：复制或移动用户音频、删除磁盘文件、把本地歌单同步到 QQ/网易云、重写现有云歌单接口、修改电影视觉系统。

## 架构

### Electron 本地数据层

新增独立本地曲库数据模块，由 Electron 主进程读写 `app.getPath('userData')` 下的版本化 JSON 文件。文件只保存文件夹路径、歌曲索引、歌单和歌曲引用，不保存音频或歌词文件副本。

写入采用临时文件加替换的原子写入方式。读取失败时保留损坏文件并回退为空索引，避免启动失败。数据结构带 `version` 字段，便于后续迁移。

主进程负责：

- 添加和移除曲库文件夹记录。
- 启动时及用户导入时递归扫描所有已登记文件夹。
- 生成当前会话可用的本地音频 token。
- 合并扫描结果并返回可播放、失效和更新后的歌曲状态。
- 保存和读取本地歌单。
- 对本地歌曲和歌单操作做校验、去重和持久化。

渲染进程负责界面状态、歌曲选择、播放队列和搜索结果展示，不直接读写任意磁盘路径。

### 数据模型

曲库文件夹记录：

```js
{
  id: "folder:<stable-hash>",
  path: "D:\\Music",
  name: "Music",
  addedAt: 0,
  lastScannedAt: 0,
  status: "available" // available | missing | unreadable
}
```

本地歌曲索引：

```js
{
  id: "local:<stable-id>",
  folderId: "folder:<stable-hash>",
  relativePath: "Artist\\Song.mp3",
  filePath: "D:\\Music\\Artist\\Song.mp3",
  fileSize: 0,
  modifiedAt: 0,
  name: "Song",
  artist: "Artist",
  album: "Artist",
  format: "mp3",
  lyricRelativePath: "Artist\\Song.lrc",
  available: true,
  lastSeenAt: 0
}
```

稳定歌曲 ID 优先基于规范化绝对路径生成。文件在原文件夹内更新时保留 ID；再次扫描相同路径会更新大小、修改时间、歌词和播放 token，不生成重复歌曲。不同文件夹中标准化歌曲名和歌手相同的歌曲在搜索展示时去重，但曲库索引仍保留各自文件记录，避免错误删除用户文件关系。

本地歌单：

```js
{
  id: "playlist:<uuid>",
  name: "我的歌单",
  createdAt: 0,
  updatedAt: 0,
  items: [
    { ref: "local:<stable-id>", provider: "local", snapshot: {} },
    { ref: "qq:<song-id>", provider: "qq", snapshot: {} },
    { ref: "netease:<song-id>", provider: "netease", snapshot: {} }
  ]
}
```

云歌曲 `snapshot` 保存播放所需的现有歌曲元数据。播放时仍走原有 QQ 或网易云接口，并遵守登录状态。删除歌单只删除歌单记录，不修改曲库索引或磁盘文件。

## 本地曲库行为

导入文件夹后，将文件夹加入永久登记列表并立即扫描。新结果与现有曲库合并，不替换当前已有歌曲。再次导入同一路径只刷新该文件夹。

启动时后台重新扫描已登记文件夹：

- 文件存在时刷新元数据、歌词和播放 token。
- 文件夹或文件暂时不可访问时保留索引，标记为失效。
- 用户重新连接磁盘或重新导入原位置后自动恢复。
- 播放失效歌曲时提示文件不可用，不主动删除歌单项目。

支持格式继续沿用现有音频和歌词扩展名集合。歌词优先匹配同目录同基础文件名；额外识别常见译文后缀，例如 `.trans`、`.translation`、`.cn` 和 `.zh`。

## 本地曲库与歌单界面

左侧歌单面板增加“本地曲库”入口，与现有队列和云歌单共存，不重写 3D 歌单架的数据来源。

本地曲库列表采用分批渲染，避免一次性创建全部歌曲节点。工具栏包含：

- 导入文件夹。
- 全选。
- 反选。
- 取消选择。
- 加入歌单。

每首歌曲提供复选框、播放操作和可用状态。批量加入时可以选择已有本地歌单或创建新歌单。重复加入同一歌单的同一歌曲时跳过重复项并反馈新增数量。

本地歌单区域提供新建入口。每个歌单支持打开、播放全部、重命名和删除。删除前二次确认，确认文案明确说明不会删除歌曲文件。

选择歌单播放时，按歌单顺序生成 `playQueue`。本地歌曲使用重新扫描生成的 token；云歌曲使用保存的快照并走现有平台播放链。失效或当前未登录来源的歌曲保留在歌单中，播放时给出明确提示并允许用户继续选择其它歌曲。

## 搜索规则

搜索候选来源由登录状态决定：

- QQ 和网易云均未登录：只搜索本地曲库。
- 只登录 QQ：搜索本地曲库和 QQ。
- 只登录网易云：搜索本地曲库和网易云。
- 两个平台都登录：搜索本地曲库、QQ 和网易云。

综合搜索结果按 `本地 > QQ > 网易云` 排序。歌曲去重键由规范化歌曲名和主歌手组成，忽略大小写、首尾空格和常见标点差异。同一去重键只保留优先级最高且可用的结果；若最高优先级本地文件失效，则允许展示下一可用平台结果。

用户手动切换 QQ 或网易云搜索标签时，只查询对应来源。未登录时展示静态提示和显式登录入口，不自动弹出登录窗口。游客登录不改变平台登录状态。

## 歌词模式

底部歌词按钮使用固定宽度，主文字为“词”，右下角使用较小字号显示状态：

- 词（关）：不显示舞台歌词。
- 词（开）：只显示当前时间节点。
- 词（滚）：显示七个时间节点，当前节点位于中心。

括号状态通过独立 `span` 和 CSS 下标布局实现，不依赖不完整的中文 Unicode 下标字符。点击按“关、开、滚、关”循环，模式持久化到现有视觉设置存档。按钮标题和可访问标签同步描述当前状态。

滚动模式始终维护当前歌词前后三个节点，共七个歌词节点。节点切换时使用现有舞台歌词坐标系和平滑插值移动，不创建整首歌词对应的 3D 对象。当前节点高亮并显示逐字或逐行进度；非当前节点降低亮度和发光，避免遮挡 3D 歌单详情页。

“双行歌词”旧设置替换为“显示译文”独立开关：

- 关闭时只显示原文。
- 开启且存在译文时，一个时间节点显示原文和较小字号译文。
- 无译文时不预留空行。
- 单节点模式中的原文加译文仍属于一个歌词节点。
- 七节点模式显示七个时间节点，每个节点可以带一行译文。

## 译文解析与时间轴对齐

云端接口已有 `tlyric` 字段，前端分别解析原文和译文。匹配算法保持顺序单调，不能重复使用译文行：

1. 过滤元数据行和空行并按时间排序。
2. 优先匹配时间差不超过 `0.35` 秒的行。
3. 未匹配时，在相邻原文时间间隔基础上计算动态容差，最大不超过 `3.5` 秒。
4. 从当前译文游标开始选择最近且未使用的译文，禁止向前回配。
5. 超出容差的译文不强行绑定，避免整首歌词错位。

本地歌词支持两类双语格式：

- 原文和译文分别位于同名歌词及常见译文后缀文件中，使用上述算法对齐。
- 单个 LRC 中相同时间戳连续出现两条不同文本时，第一条作为原文、第二条作为译文合并。仅对相同时间戳执行该规则，避免把普通相邻歌词误判为译文。

## 错误与恢复

- 索引 JSON 读取失败：保留原文件并创建新的空状态，界面提示曲库索引需要重新建立。
- 文件夹不可访问：标记文件夹和歌曲失效，不删除记录。
- 单个文件读取失败：跳过该文件并继续扫描其余文件。
- 歌单引用不存在：保留失效项目快照，允许用户手动移除。
- 云歌曲平台未登录：不自动弹窗，提示用户显式登录或跳过。
- 搜索某一来源失败：继续展示其它可用来源结果，并标记失败来源。

## 测试与验证

自动测试覆盖：

- 多文件夹合并、重复导入去重和跨重启恢复。
- 文件夹丢失后的失效保留与恢复。
- 本地歌单增删改、歌曲批量选择和重复项跳过。
- 混合来源歌单序列化与队列恢复。
- 登录状态对应的搜索来源选择、优先级排序和自动去重。
- 歌词三态循环、设置持久化和固定宽度按钮结构。
- 七节点窗口计算、当前行居中和边界歌曲处理。
- 译文精确匹配、偏移匹配、禁止重复匹配及超出容差不匹配。
- 单文件相同时间戳双语 LRC 合并。

完成后运行现有全部静态测试、Node 语法检查、HTML 内联脚本解析和 `git diff --check`。使用实际 Electron 验证文件夹导入、重启恢复、歌单批量操作、三种歌词状态、译文开关、搜索登录规则和混合歌单播放。发布时再执行 Windows 目录构建与安装包构建。

## 兼容边界

- 不恢复自动登录弹窗；只有用户显式操作才打开平台登录。
- 不覆盖现有用户视觉存档，只为缺失字段提供默认值和迁移。
- 不一次性渲染完整本地曲库或整首 3D 歌词。
- 不改变现有玻璃质感、电影视觉系统、播放暂停控制链和 3D 歌单架层级规则。
- 不把本地歌单伪装成网易云或 QQ 云歌单，也不调用云端歌单写入接口。
