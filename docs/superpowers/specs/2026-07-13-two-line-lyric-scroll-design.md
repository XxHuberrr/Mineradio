# Mineradio 双行歌词与两行滚动优化设计

## 目标

将歌词设置中的“显示译文”改为“歌词双行显示”开关，并把滚动歌词从七行改为两行。修复切句时销毁并重建全部歌词网格导致的瞬时卡顿，同时保留现有 Three.js 舞台绑定、歌词高亮和 3D 歌单架避让规则。

## 最终交互

- `词（关）`：不显示舞台歌词。
- `词（开）`：双行开关关闭时只显示当前句；双行开关开启时显示当前句和下一句。
- `词（滚）`：固定显示当前句和下一句，切句时两行平滑向上滚动。
- 设置项名称为“歌词双行显示”，不再表示原文和译文。
- 本轮不在舞台歌词中显示翻译歌词；云端和本地译文解析字段可以保留，但不参与舞台文字组合。

## 卡顿根因

当前 `showStageScroll()` 在每次当前歌词索引变化时调用 `clearStageScrollMeshes()`，随后为可见窗口重新执行多次 `buildLyricMesh()`。每个网格会创建高分辨率 CanvasTexture、ShaderMaterial、发光平面和粒子几何体。七套对象在切句同一帧集中创建和销毁，导致主线程和 GPU 上传出现明显峰值。

## 优化架构

滚动模式维护固定两个槽位：当前句槽位和下一句槽位。每个槽位记录歌词索引、文本和目标位置。

切句时：

1. 原下一句网格成为新的当前句网格，不销毁。
2. 原当前句网格移动到上方并淡出，动画结束后复用为新的下一句槽位。
3. 只有新进入窗口的歌词文本与复用网格文本不同时，才替换该槽位的纹理和文字资源。
4. 两个槽位的位置、透明度和缩放均按帧插值，不使用整组瞬间跳位。

歌词纹理增加有界缓存，以最终绘制文本和影响绘制的字体参数组成缓存键。缓存采用最近使用顺序并限制数量，避免无限占用显存。清理歌词系统时只释放不再被槽位或缓存引用的资源。

## 双行模式

新增设置字段 `lyricDoubleLine`，默认关闭。读取旧存档时，如果存在旧版 `lyricDoubleLine` 则沿用；不再从 `lyricShowTranslation` 自动迁移，避免把用户此前的译文偏好误认为当前句加下一句。

`composeStageLyricText()` 的规则：

- 单行模式返回当前句。
- 双行开关开启且处于 `词（开）` 时返回当前句加下一句。
- `词（滚）` 每个槽位只包含对应的一句歌词，由两个槽位共同构成两行，不在单个网格中重复拼接下一句。

## 测试与验证

- 静态测试确认设置项名称、`lyricDoubleLine` 持久化和旧译文开关移除。
- 纯逻辑测试确认滚动窗口固定为两个节点。
- 静态测试确认滚动更新不再每次调用 `clearStageScrollMeshes()` 后重建全部网格。
- 性能诊断计数器记录每次切句创建和复用的网格数量；稳定播放后单次切句最多替换一个槽位文本。
- 运行全部现有测试、语法检查、HTML 内联脚本解析和 `git diff --check`。
- 使用 Electron 进程级启动检查，并重新生成目录版和安装包。

## 兼容边界

- 不修改歌词世界坐标、镜头绑定、颜色、发光和歌单详情页透明度规则。
- 不一次性预生成整首歌词网格。
- 不改用 DOM 歌词层。
- 不恢复导入覆盖、本地歌单丢失或游客自动弹登录窗口等旧问题。
