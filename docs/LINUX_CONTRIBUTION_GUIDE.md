# Mineradio Linux 贡献路线

## 当前项目状态

当前仓库已经完成这些基础工作：

- 已移除桌面歌词功能
- 已移除壁纸模式功能
- 已去掉对应的 Windows-only overlay IPC / preload / WorkerW / PowerShell 路径
- 已补齐基础 Linux 适配
- 已将默认 GPU 压力做保守下调
- 已能在本机构建出 Linux `dir` 产物

当前本机可运行产物：

```bash
./dist/linux-unpacked/mineradio
```

## 现在最适合的贡献方向

按收益排序，最推荐：

1. 先把 Linux 版真正做成可分发产物
2. 再做 Linux 实机兼容性修复
3. 再做更广覆盖的 Linux 打包支持

---

## 路线 A：先把 Linux 版做成可分发

### 目标

让项目不仅能产出 `linux-unpacked/` 目录，还能产出更方便使用的 Linux 包。

### 最推荐的第一步

先做 **AppImage**。

原因：

- 对 Linux 用户最省事
- 跨发行版能力比 `dir` 更强
- 比 deb / rpm / pacman 更适合先落地

### 你要做的事

1. 查看 electron-builder 的 Linux / AppImage 文档
2. 把 `package.json` 的 Linux target 从 `dir` 改为 `AppImage`
3. 在本机补齐 AppImage 所需工具
4. 重新构建
5. 在本机实际运行验证

### 参考步骤

先检查本机是否有相关工具：

```bash
which appimagetool
```

如果没有，再按 Arch 的方式安装。

然后把 Linux target 从类似：

```json
"target": [{ "target": "dir", "arch": ["x64"] }]
```

改成：

```json
"target": [{ "target": "AppImage", "arch": ["x64"] }]
```

然后构建：

```bash
npm run build:linux
```

## 路线 B：做 Linux 实机兼容性修复

如果目标是“我本机先稳定能用”，这条路线也很重要。

### 先做什么

直接运行：

```bash
./dist/linux-unpacked/mineradio
```

然后记录真实问题。

### 最值得观察的点

- 启动是否报错
- 窗口是否正常显示
- 有没有黑屏 / 透明异常
- GPU 占用是否异常
- CPU 占用是否异常
- 音频播放是否正常
- 登录窗口是否正常
- 全屏行为是否正常
- 字体渲染是否异常
- 搜索 / 播放 / 切歌是否稳定
- 切换到不同 DE 后是否还能正常显示和交互

### 贡献方式

每发现一个问题，都尽量整理成：

- 现象
- 触发步骤
- 当前行为
- 期望行为
- 机器环境
- 日志 / 截图

这类贡献价值很高，因为跨平台项目最缺真实 Linux 机器上的可复现问题。

---

## 路线 C：做更系统的 Linux 支持

如果后续想长期贡献，不只是修自己本机能用，可以继续推进：

### 1. 平台能力整理

建议逐步明确：

| 功能 | Windows | Linux |
|---|---|---|
| 播放 | 支持 | 支持 |
| 登录 | 支持 | 支持 |
| 桌面歌词 | 已移除 | 不支持 |
| 壁纸模式 | 已移除 | 不支持 |
| 自动更新 | Windows 仍保留链路 | Linux 暂以手动更新为主 |

### 2. 多种 Linux 产物

后续可继续支持：

- AppImage
- deb
- rpm
- pacman / Arch 包

但这一步不建议一开始就做，维护成本高。

---

## 路线 D：做构建质量守门

如果想做维护型贡献，可以补构建后验证。

### 每次 Linux 构建后应确认

- 主程序能启动
- 不该打包的死文件不在包里
- 核心运行文件都在
- 运行时不再引用已删除功能

例如可检查：

- `desktop-lyrics.html` 不在包里
- `wallpaper.html` 不在包里
- `overlay-preload.js` 不在包里
- 主程序能启动

---

## 你现在最推荐的实际行动清单

### 今日版本

1. 切换到目标 DE，运行当前 Linux 产物
2. 记录 DE 下是否存在窗口 / 输入 / 渲染 / 全屏问题
3. 如果没问题，再继续推进 AppImage
4. 如果有问题，优先修实机问题，再做更高级打包

---

## 如果你要正式贡献，最重要的三件事

### 1. 先跑

- 构建
- 启动
- 观察问题

### 2. 再改

- 一次只修一类问题
- 改完立刻重跑验证

### 3. 带证据

- 能运行
- 能复现
- 能验证修好

“改了能跑”比“我觉得代码更优雅”重要。

---

## 当前最建议的下一步

如果你的主要目标是本机自用，当前最合理顺序：

1. 切换到目标 DE 运行 `./dist/linux-unpacked/mineradio`
2. 看是否存在实际问题
3. 把问题逐条修掉
4. 问题稳定后，再把 Linux 产物升级为 AppImage

---

## 本机切换 DE 后的快速检查清单

切过去之后建议依次看：

1. 程序是否能启动
2. 主窗口是否能显示
3. 鼠标点击是否正常
4. 搜索是否正常
5. 登录窗口是否正常弹出
6. 音乐是否能播放
7. 全屏是否正常
8. GPU / CPU 占用是否合理
9. 窗口阴影、透明、圆角是否异常
10. 关闭 / 再打开是否稳定

---

## 当前这条线的核心目标

不是一上来追求“所有 Linux 都完美支持”，而是先把它推进到：

- 本机能稳定用
- Linux 构建链稳定
- 分发形式逐步完善

这才是最有效的贡献路线。
