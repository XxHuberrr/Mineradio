# 更新公告与旧版兼容

每次正式发布必须同时提供完整安装包和 `latest.yml` 版本说明。只发布安装包会使旧客户端在 GitHub API 访问失败时无法通过备用线路发现更新。

`docs/update/latest.yml` 只记录版本号和发布时间，不填写 `files`、`path`、`url` 或 `sha512` 等安装包下载字段。将它以 `latest.yml` 名称上传到对应 Release；不使用打包工具生成的安装更新清单。blockmap、补丁和校验文本仍不作为 Release 附件。

主检测接口成功时，软件显示 Release 正文前四条说明与 `mineradio-download-page` 标记中的网盘线路。2.1.0 的备用检测只能显示通用更新提示，点击后打开对应版本的发布页，用户再选择网盘入口。

## 2.1.0 的入口限制

- 启动约 9 秒后检查一次；失败后没有自动重试。
- 检测成功后显示右上角更新箭头，不会自动弹公告。
- 全屏、沉浸和桌面壁纸模式会隐藏该箭头所在的标题栏。
- 打开更新面板不会重新发起检查。

排查时先从托盘彻底退出并重新打开软件，切回普通窗口，等待约 30 秒后查看右上角更新箭头。网络较慢时可能需要更久。仍未出现入口时，可从本次发布公告提供的新网盘链接获取完整安装包。

上述频率、弹窗和入口限制属于已安装旧客户端的行为，不能通过修改 Release 正文远程改变。
